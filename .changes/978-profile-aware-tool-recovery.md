### Fixed

- **`@reticlehq/server` — the default surface sent agents to `reticle_run`, which it does not advertise.** The default surface is closed: it advertises everything it can call and ships no dispatch hatch. Three messages had not been told. Asking the catalogue about a name that moved — `reticle_tools { names: ["reticle_coverage"] }` — answered "Call `reticle_verify { action: "coverage", ... }` — through `reticle_run` if it is not advertised under this profile", and calling a merged name directly (`reticle_diff`, `reticle_record_start`, `reticle_flow_list`, `reticle_lease_acquire`, …) answered the same way. Both sentences named a tool that is not on that surface, so an agent that followed the recovery spent a turn to be told `reticle_run` does not exist — and a wrong remedy is more expensive than no remedy, because it gets followed.

  Every one of those messages now derives its route from the live surface. Where the tool it points at is advertised, you get the call and nothing else (`reticle_coverage` → "Call `reticle_verify { action: "coverage", ... }`."). Where it is not and the hatch IS advertised, you get the `reticle_run` call written out. Where neither is reachable, you get the only thing that actually opens it: start the daemon with `RETICLE_ADVERTISE_ALL_TOOLS=1`, plus `reticle_tools {}` for what this surface does advertise. Surfaces that carry `reticle_run` are unchanged and still point at it. Closes [#978](https://github.com/reticlehq/reticle/issues/978).
