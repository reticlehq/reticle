### Fixed

- **`@reticlehq/server` — a request that a click sent just before a full page load was not in the record.** A "Sign out" button that sends a `fetch()` POST and then loads `/sign-in` with `location.href` or `location.assign()` got `verified: "no"` and "no network call matched" on a `net` check, and the POST was missing from every later `reticle_observe { action: "network" }`. The old document sent the POST's records, but the new document connects as a new session, and only that session was read. The new session now gets the network records that the old document made during the agent's newest action. Each one has `fromDepartedDocument: true`. A request whose page unloaded before its answer arrived is marked `pageUnloaded: true`, and a `net` check that only it can answer is `unknown` with the reason, never `no`. A client-side route change (`history.pushState`, a router's `push`) already kept the request and is unchanged. When `reticle_act_and_wait` refuses `since`, the refusal now names `reticle_assert { predicate, since }`. Closes [#1944](https://github.com/reticlehq/reticle/issues/1944).
