### Changed

- **An app nobody wired gets a verdict on the first call that needs a page.** Installed through the MCP server alone (a plugin, or a hand-written `npx @reticlehq/server mcp` config), `init` never runs, and the first `reticle_look` used to stop at "no browser session connected". Now, when exactly one dev server is running inside the project's folder, Reticle opens it in its own browser with the SDK supplied and answers the call, with one notice saying what that tab cannot see (component state, source file:line) and the command that wires the app for good. Where it cannot tell which server is the app's (several running, or no way to see which folder a server runs in, as on Windows), nothing is opened: the answer names the `reticle_lease` call that gets a verdict now and the init command.
- **The no-session answer hands over this project's own init command.** `next_action` for an unwired app now runs `init` in the app's own folder (`cd web && …` in a monorepo) through the project's own runner (`pnpm dlx`, `bunx`, `yarn dlx` on Yarn 2+, else `npx`), and says to restart the dev server and reload afterwards. A Bun project's dev command is now `bun run dev`.
- **The rules `init` writes say what to do when no app is connected at all:** run `init` in the app's own folder yourself.
