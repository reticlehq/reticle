### Fixed

- **`@reticlehq/server` — a flow replay could click the wrong element and report a pass.** A flow recorded against a `role` anchor — "View result" on row 3 of a table — replayed by clicking the FIRST live element with that name and returned `ok: true`. When every row shares the consequence (the same `GET` returning 200), the replay PASSED: a green verdict for an action on the wrong element, which is the one claim a replay exists to refuse. The testid path already returned an ambiguous drift here; the role runner was the one that guessed. A role anchor resolving to two or more elements now returns `anchor_ambiguous`, dispatches nothing, and says how many it matched — the same answer testid gives.
- **`@reticlehq/server` — the same defect, for a `component` anchor, and there it was the ordinary case.** `by:'component'` matches by component NAME, and a component rendered once per row — a table's action button, a card's menu — matches as many times as there are rows, so `runComponentStep` guessing `refs[0]` was not an edge case but the everyday one. It now answers `anchor_ambiguous` too. The three anchor runners share one rule (`ambiguityDrift`) instead of each carrying a copy — written per-runner, the check had been applied to two anchor kinds and forgotten for the third.
- **`@reticlehq/server` — the stale-ref retry no longer reports an ambiguity as a dead element.** A re-render between the two dispatches can turn an unambiguous anchor into an ambiguous one, and the retry then has nothing to dispatch at. It used to answer with the staleness it was retrying for — `error: "ref 'e-orig' no longer resolves to an element"` — a sentence about an element that is GONE, sent for an element that is now three. An agent reading that hunts for a rename or re-records the flow; the actual fix is a narrower anchor. The retry now reports `anchor_ambiguous` as a drift, and a retry that finds the element genuinely gone still reports the stale-ref failure. The retry predicates of all three runners are one function for the same reason as above.

Closes [#1227](https://github.com/reticlehq/reticle/issues/1227).
