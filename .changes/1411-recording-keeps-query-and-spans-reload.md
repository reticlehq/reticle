### Fixed

- **`@reticlehq/server`: a recording keeps the query it started on, and stopping one across a page load no longer reports a negative window.** A journey recorded on `/products?scope=TOPWEAR` saved `startPath: "/products"`, so its replay started on the unfiltered page. `startPath` now keeps the app's query, without Reticle's own url params, and replay reads a leased tab's url the same way, so a tab already on that page is not re-navigated. A recording that crossed a full-page load reported a negative `window_ms` and an empty span, because the reconnected page is a new session whose clock restarts. Stop now notices that the span ended on a different page, reads that page from its start, and says in `warning` that the report covers only the page that loaded. Closes [#1411](https://github.com/reticlehq/reticle/issues/1411).
