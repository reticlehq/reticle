### Fixed

- **`@reticlehq/server` — the Harness reported its own wrong guesses as app failures.** When the driver declared that an in-page control (a Mine/Team toggle, a project picker, a dialog, a tab) would change the route and it did not, the miss counted as a failed check and a finding, so runs whose every goal was met read NOT PROVED. A check that claimed nothing but a route and missed is now the driver's error: not a failed check, not a finding, and undecided in the synced run. The answer no longer contradicts itself either: `proved` is the headline's own word (and a met set of checks with a missed goal reads NOT PROVED), the summary no longer quotes the driver's own account (it named flows that were never saved; it stays in `driverAccount`), and a planned run reports the credits its journeys spent.
