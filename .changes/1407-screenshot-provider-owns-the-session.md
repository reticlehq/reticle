### Fixed

- **`@reticlehq/server`: `reticle_screenshot` and `reticle_visual_diff` never save another tab's pixels.** While a browser started by `reticle drive` was alive, a screenshot or diff named for a different session (your own tab, or a lease) photographed the driven page instead and answered `saved: true`, so a baseline could be written from one page and compared against another. A capture now goes through the driven-browser provider only when that provider is driving the named session's page, the same check every real-input gesture already makes. Otherwise it falls through to the desktop and lease routes, or answers `no-visual-provider` for that session. The launched provider also refuses a url it does not own, by the same rule. Closes [#1407](https://github.com/reticlehq/reticle/issues/1407).
