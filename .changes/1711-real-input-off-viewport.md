### Fixed

- **`@reticlehq/server` + `@reticlehq/browser` + `@reticlehq/core` — a real hover, click or drag on an element outside the viewport no longer reports `performed: true` while the pointer lands on nothing.** The real-input path aimed at the box that `INSPECT` returned, and for an element above or below the viewport that box was off the page. The synthetic path scrolled the target in first, and the real path did not. `INSPECT` now takes an opt-in `reveal` argument: the page scrolls an off-viewport element to the center, then measures it. The result says `scrolledIntoView: true`. The real-input path uses it for the target and for the drop target of a drag. If the box is still outside the viewport, a click or drag goes to the synthetic path with `element-not-locatable` (or `drag-target-unresolved`), and a hover is refused. When scrolling the drop target in moves the page, the drag reads the source box again. Closes [#1711](https://github.com/reticlehq/reticle/issues/1711).
