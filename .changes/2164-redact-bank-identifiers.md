### Security

- **`@reticlehq/core` — bank-transfer identifiers (`iban`, `accountNumber`, `routingNumber`, `sortCode`) were not redacted by the wire key rule.** `PAYMENT_FIELD_WORDS` already treated IBAN, account number, routing number and sort code as payment-sensitive so the Harness refused to type into them, but `SENSITIVE_KEY` did not cover them. A bank-transfer or payout request body carrying `iban`, `accountNumber`, `routingNumber` or `sortCode` reached the agent transcript and the on-disk journal (`~/.reticle`) in clear. `SENSITIVE_KEY` now redacts `iban`, `(?:acct|account)[-_]?(?:numbers?|num|no)(?:[-_]?last4)?(?=$|[-_])`, `routing[-_]?number(?=$|[-_])` and `sort[-_]?code(?=$|[-_])`. Because `isCredentialFieldName` shares this rule, a recorded fill into an IBAN or account-number field becomes a `RETICLE_SECRET_FIELD_*` variable, and replay needs that variable. Ordinary application keys (`account`, `accountId`, `accountType`, `accountName`, `routingPath`, `sortOrder`, `sortBy`, `code`, `acct`) remain visible. Closes [#2164](https://github.com/reticlehq/reticle/issues/2164).
