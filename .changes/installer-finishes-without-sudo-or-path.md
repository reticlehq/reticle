### Fixed

- **The one-line installers finish when npm's global folder needs sudo, or its bin is not on PATH.** `install.sh` and `install.ps1` used to stop on both, after the package was already on disk and before any coding agent was registered. An `EACCES`/`EPERM` global install now goes into `~/.reticle/npm` instead; a bin that is not on PATH (a Node installed a minute ago, a custom npm prefix) is run by its full path. The next steps open with the one line that puts it on PATH for the person's own shell (zsh, bash, fish, PowerShell), and PowerShell adds it to the open window. An older `reticle` first on PATH is no longer the one that runs.
- **The installers' next steps match the machine.** A machine with no coding agent was told to "restart" one and saw "Registered with the coding agents"; it now gets `reticle init` as step one. Somebody who ran the installer inside their app is told to run `reticle init` in that folder instead of `cd your-app`. `reticle setup install` reports both facts on one line the installers read and hide.
- **A failed install on a company network says what to set.** A registry npm cannot reach names `npm config set proxy` / `https-proxy` and a mirror registry; a proxy that re-signs HTTPS names `NODE_EXTRA_CA_CERTS` / `cafile`, instead of npm's stack trace alone.
