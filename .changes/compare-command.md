### Added

- **`@reticlehq/server` — `reticle compare <reference-url> <candidate-url>` lists what users would see change between two builds.** Use it to compare main with a pull request preview, or a known-good build with a changed build. The app needs nothing installed: each run is a tab that the daemon leases, and a page with no Reticle SDK gets the daemon's own reader. The command has one recipe and no settings. It plans every action on every control of the reference, breadth first, with an edge value for each field and the values the app's own scripts compare each field with. It reads each page only when it settles, and also compares the network calls and console errors that each sequence caused. It drives the plan on the reference two times and on the candidate one time, and ignores the lines that change between the two reference runs. Each difference prints the steps that reproduce it and its `-` and `+` lines. `--base <url>` tags each difference as a regression, a missed target or a change, and prints a score. `--json` prints one object. Exit `0` means same, `1` different, and `2` that the run proves nothing (a lost browser session, or an error).
