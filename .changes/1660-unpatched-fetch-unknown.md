### Fixed

- **`@reticlehq/browser`, `@reticlehq/engine` — a request sent through a `fetch` saved before Reticle connected read as `no`, not `unknown`.** Some client libraries store `window.fetch` when their module loads. Reticle patches `fetch` later, at `connect()`, so a call through the stored function made no record, and a `net` clause over it said "no call matched" while the server got the request. The SDK now reads the browser's resource timing for such calls and sends a new `net.unpatched` event. It has no method, and its status is only a hint. A `net` miss over a matching URL is now `unknown`. The reason says that the request went through a `fetch` saved before Reticle connected, and tells you to connect Reticle earlier through the build plugin. A request that the patched `fetch` saw still gives one record and one verdict. Closes [#1660](https://github.com/reticlehq/reticle/issues/1660).
