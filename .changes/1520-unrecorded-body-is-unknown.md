### Fixed

- **`@reticlehq/engine`, `@reticlehq/browser`: a body clause over a body that was not recorded answered `no`.** With body capture on, the SDK still skips some response bodies on purpose: a streamed response (`text/event-stream`, for example a streamable-HTTP MCP endpoint) is never read, because reading it would hang the app. A `net` clause with `bodyContains` or `bodyMatches` over such a call came back `verified: "no"`, as if the body did not contain the text. The message also told you to enable `captureNetworkBodies`, which was already on. A body clause over an unrecorded body, response or request, is now `unknown`. The SDK marks a body it skips with capture on (`responseBodyReason`: `streaming`, `not-text` or `unreadable`), and the message follows that reason. For a stream, it points you at a DOM or state clause, or a non-streaming endpoint. The `captureNetworkBodies` remedy appears only when no reason was marked, which means capture was off or the SDK is older. Closes [#1520](https://github.com/reticlehq/reticle/issues/1520).
