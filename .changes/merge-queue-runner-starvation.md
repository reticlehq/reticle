### Fixed

- **A merge-queue entry no longer asks for the full Windows install matrix, which was starving the runner pool.** `merge_group` is not `pull_request`, so every queue entry fell into the full-matrix branch and requested twenty install cells, ten of them Windows — a load this workflow's own comments already record as more than the runner pool hands out for a single run. With five entries building at once, the second wave of every run sat queued, nothing ran anywhere in the repository for over two hours, and the queue's one-hour check timeout expired. Entries left the queue `CLEAN`, with no failing check and no CI run behind them, which reads as flaky pull requests and is a starved pool. A queue entry now gets the same three Windows scaffolds a pull request does; the nightly schedule and `workflow_dispatch` still run all ten, so coverage is rescheduled rather than reduced.
