### Fixed

- **`@reticlehq/server`: a page that dials the bridge on the wrong path is named in the no-session diagnosis.** A `connect({ url })` with an explicit path other than `/reticle`, such as `ws://localhost:4400/ws`, got a bare 400 from `ws`'s own path check before the origin gate ran. That left no trace, so the no-session error listed its usual causes without the one that applied. The bridge now records each upgrade turned away for its path, the same way it records an origin refusal. The no-session error names the path that was asked for and says the bridge listens on `/reticle` only. Because the upgrade is answered before any origin check, it doesn't claim the app is running. Only the pathname is kept, never the query, which can carry a pairing token. Closes [#1242](https://github.com/reticlehq/reticle/issues/1242).
