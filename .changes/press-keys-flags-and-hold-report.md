### Fixed

- **`@reticlehq/browser` — a modifier named in `press { keys: [...] }` now sets its own event flag.** `modifiers` is a fixed set of flags for one event, which is exactly why `keys` exists: a SEQUENCE whose held state changes partway through. The multi-key dispatcher read its flags from `args.modifiers` alone, so `{ keys: ['Control', 'k'] }` pressed Control and then dispatched the `k` keydown with `ctrlKey: false` — a shortcut handler checking `event.ctrlKey` did nothing while the action reported `dispatched: true`. The flag timing is the browser's own, read off a real Chromium rather than assumed: a modifier's own keydown carries its flag already true, its own keyup already false, and every event between carries the held state. Closes [#1294](https://github.com/reticlehq/reticle/issues/1294).

- **`@reticlehq/server` — a real held press can no longer leave the key down.** If the wait between `keyboard.down` and `keyboard.up` failed, the release never ran, and the caller then fell back to the synthetic path and pressed the same key a second time. On a live browser the key or modifier stayed held and coloured every later action for the rest of the run. The failure path now releases best-effort before rethrowing; a failed release on the ordinary path still surfaces as a real error rather than being swallowed. Closes [#1295](https://github.com/reticlehq/reticle/issues/1295).

- **`@reticlehq/server` — `effect.heldMs` now reports the hold achieved on a real-keyboard press too.** `reticle_act` promises `effect.heldMs` says what was achieved, and on the real path the act result IS the effect block — but the driver's measurement was dropped on the way out, so an agent confirming a hold-to-confirm control armed read `undefined` on exactly the path `holdMs` had just been added to. The number is now measured (not echoed back) and forwarded, and is absent rather than `0` when the press held nothing. Closes [#1296](https://github.com/reticlehq/reticle/issues/1296).
