### Added

- **`@reticlehq/server` — the Harness looks around before it drives, and hunts before it grades.** Before a drive it surveys the app with no model (each nav link and toggle pressed once, never a field or a write) and keeps the map in `.reticle/plans/harness-map.json`, refreshed by every drive and surveyed again after a day; the platform's engine looks a goal up in it. After the drive, a goal not on the page it ended on is hunted for like a person would: the toggles and tabs there (Mine → Team), the controls the journey names (a menu that opens is followed into its items), the same page without its search or filter, and the pages the map says show it. A goal it still cannot find is undecided and says where it looked.
- **`@reticlehq/core` / `@reticlehq/server` — two-way testing.** When the coding agent in the same app judged a goal the Harness was given, the explore answer and the Harness run carry `disparity`: `findable` (both proved it), `discoverability` (the agent proved it, the Harness could not find it), `agent_assumption` or `defect`, with what the Harness searched and where it gave up.
