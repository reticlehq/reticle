### Fixed

- **A failed `reticle init` now leads with what the daemon knows, instead of contradicting it.** When no session appeared, setup printed one sentence about the page: "the SDK IS in the page and never dialled the bridge", followed by three candidate causes. On a machine where a daemon belonging to another project held the bridge port, that was the opposite of the truth — the SDK dialled, presented its pairing token and was refused, and the daemon had recorded exactly that a second earlier. All three causes offered were wrong, and each one sent the reader to inspect something that was fine. The daemon's diagnosis is the only place a refused connection can be seen at all, so it is printed first now, with the page finding after it. The page finding is unchanged, and a daemon that cannot be reached still leaves the run with its own verdict.
