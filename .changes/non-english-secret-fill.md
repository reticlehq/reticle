### Security

- **`@reticlehq/server` — a password typed into a field with a non-English name was saved in clear in a flow file.** Two paths caused it. A live `reticle_act_sequence` step dropped the SDK's `secret` mark, so a password field in a sequence was redacted only when its name was English. An SDK before 3.8.0 sends no mark, and the server's name rule was English only, so a field named "Пароль" was saved verbatim on every save path. Flow files are often committed, so the password went into git. Now the sequence step keeps the mark, and a fill is also redacted when its field name is the word for a password, a PIN or a one-time code in one of about 30 languages (`isCredentialFieldName` in `@reticlehq/core`). An already anchored flow that an older in-page recorder saved is redacted by the same rule. A field with a non-ASCII name now gets its own variable, `RETICLE_SECRET_FIELD_<hash>`. Before, "Пароль" and "Гасло" both became `RETICLE_SECRET__`, and a replay could type one field's value into the other. A flow that names the earlier variable still reads it. Rotate a password that a saved flow holds in clear, and remove it from your git history.
