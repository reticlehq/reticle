### Fixed

- **`@reticlehq/server` — `press` now reaches a real keyboard, so Tab order can be verified.** A `press` with no `ref` (Escape, Tab, a modifier shortcut) is a document key, and it was dispatched as a synthetic `KeyboardEvent` even when real input was configured. A synthetic key event does not move focus, so `press { text: "Tab" }` reported `dispatched: true` over a page where focus had not moved — and there was no mode in which an agent could check keyboard focus order at all. A document key now goes through the driver's keyboard when one is configured, and the result's `inputMode` says which path ran. Two `press`es deliberately stay synthetic and say so via `inputModeReason`: one that named a `ref` (dispatching AT that element reaches it exactly, while a real keyboard sends the key to whatever holds focus) and one that named `keys` (several keys held down together, which has no `page.keyboard.press` spelling). Closes [#1176](https://github.com/reticlehq/reticle/issues/1176).
