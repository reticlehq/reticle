### Added

- **`@reticlehq/browser` — a new `insertText` action types into rich-text editors, where `fill` and `type` were refused and `press` inserted nothing.** A Tiptap, ProseMirror, Quill or Lexical editor holds its own document model, so writing `textContent` would look right and submit the old content. `insertText` takes `{ text }` and goes through the browser editing pipeline instead: it announces `beforeinput` first, so an editor that owns its input can take the text, then lets the browser insert it, so the editor model updates. EditContext surfaces (Monaco, CodeMirror 6) update through their own text model. A native command that exists and fails is refused, rather than writing the DOM while the model stays stale. `effect.valueChanged` reports whether the surface's text actually changed. Closes [#1814](https://github.com/reticlehq/reticle/issues/1814).
