### Fixed

- **`@reticlehq/server`: a parameter of a different action of the same tool is refused, not silently dropped.** The unknown-parameter check ran against every action's parameters together, so `reticle_verify { action: "change", files, names }` accepted `names` (a parameter of `"flows"`) and replayed every affected flow, and `reticle_look { action: "page", limit }` returned the whole tree. A merged tool now refuses a key its chosen action does not declare, with the same "NOT applied" wording and the action that does take it ("`names` is a parameter of action "flows""). `sessionId`, which the dispatch routes pin onto every call, is still accepted. `reticle_baseline { action: "diff" }` declares the `name` alias it already read. Closes [#1536](https://github.com/reticlehq/reticle/issues/1536).
