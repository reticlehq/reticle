### Fixed

- **`@reticlehq/engine` — a write that bumped an optimistic-lock token got `no` with `write-field-ignored`.** The server answers a compare-and-set write with the token one higher, so the echo never repeats the value that was sent. Only a key named `version` was skipped. `lock_version` (Rails), `lockVersion`, `rowVersion`, `__v` (Mongoose) and `concurrencyStamp` (ASP.NET Identity) gave `no` on a write that applied. Now a key whose last word is `version`, or `__v`, is a lock token when the request and the echo are whole numbers and the echo is larger. `concurrencyStamp` is an opaque token, the same as `etag`. A field that the server did not keep beside the bump still gives `no`. So does `targetVersion: "1.4"` echoed as `"1.3"`, and a lock token that went down. Closes [#2174](https://github.com/reticlehq/reticle/issues/2174).
