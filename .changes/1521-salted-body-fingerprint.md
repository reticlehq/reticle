### Fixed

- **`@reticlehq/browser` — a text request body is fingerprinted by a salted hash of its canonical form, so different payloads no longer collide as one write fired twice.** Two calls to one endpoint whose JSON bodies had the same shape and the same total length — the normal case for a command bus, `{ "cmd": "accessSets" }` against `{ "cmd": "currencies" }` — produced the same `requestShape`, so the disagreement engine grouped them as a duplicate write and a passing step dropped to `unknown`. A text body's fingerprint is now a hash of its canonical JSON (keys sorted, values kept) mixed with a random per-page salt that is never written to the journal or sent on the wire: equal bodies still match, different bodies separate, and no value can be brute-forced back out of a fingerprint without the salt. Form and form-urlencoded bodies keep the existing shape fingerprint, whose keys-only rule is a separate decision. Closes [#1521](https://github.com/reticlehq/reticle/issues/1521).
