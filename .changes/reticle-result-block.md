### Added

- **`@reticlehq/server`: one "Reticle result" block at the end of every verification.** `reticle_verify` (`flows`, `change` and `explore`), a single-flow `reticle_flow_replay` and `reticle_session { action: "end" }` now return `reticleResult`, a short markdown block built by the server from the verdicts it holds: a verdict line in three words only (proved, not proved, failed; one undecided check is never proved), the yes / no / undecided counts when there is more than one check, the journeys covered, what it measured (flows replayed, time; for a Harness plan, how many journeys were replayed and how many the model drove), the screenshots (the run's folder and how many, when they share one; otherwise up to three paths), and one last line about the platform. Each fact is said once: the counts are not restated beneath the verdict line, and a single replay names its screenshot folder once rather than repeating paths its steps already carry. Linked, that line links the run on the dashboard; not linked, it says what the platform adds and how to connect, once per result. The skill now tells agents to paste the block verbatim instead of paraphrasing a verdict into a pass. A `change` verdict decided above the suite (uncovered files, a disagreeing channel) retitles the block, so a nested "proved" can never sit under an outer `no`. A Harness drive whose checks held but whose goal was not reached reads "not proved", as its `proved` does.
