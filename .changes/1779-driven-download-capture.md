### Fixed

- **`@reticlehq/server`, `@reticlehq/engine`, `@reticlehq/core` — a `net` check could not see a file the server sent as a download.** A click on an export link that the server answers with `Content-Disposition: attachment` becomes a download. On Chromium nothing the page can observe records it: no request or response event, and no CDP network event on the page. On a page Reticle drives (`reticle verify`, `reticle drive`), Reticle now listens with CDP request interception for document responses, records an attachment response with its status and headers, and lets every response through at once. The engine records that detail as a request with the initiator `download`, so a `net` check on the export's method, URL and status can pass. Its body is not captured, and its duration reads 0 because nothing timed it. Refs [#1779](https://github.com/reticlehq/reticle/issues/1779).
