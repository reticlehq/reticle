### Fixed

- **`@reticlehq/engine`, `@reticlehq/browser` — a `text` predicate's `satisfies` was graded against the first 80 characters of the text, not the text.** The page describes every element with a display-sized `text` (80 characters and an ellipsis), and `satisfies` read that: an exact `oneOf` or an end-anchored `matchesPattern` on a long consent legend failed while a role/name assertion on the same fieldset passed, and a relative `changed` could not see an edit past character 80. The `match` command now takes `fullText`, which the predicate sets when it carries a `satisfies` (and the before-reading for `changed`/`unchanged`/`increased`/`decreased` sets the same way), so the property is judged on up to 4000 characters of the text. A reading that is not the whole text is never graded on the part that came back: a longer text, a locator that matches more elements than are read in full (32), and a page whose SDK predates `fullText` (it answers with the short form and does not echo the request) all give an `inconclusive` verdict that says why. The match a verdict returns, and the text a failure quotes, stay display-sized. A `compare` whose side is a `text` reads it the same way: two texts that differed only after character 80 compared equal, and now they are different, or `inconclusive` under the same three conditions. When such a comparison fails, each side is quoted as a bounded slice, and the message says so when the two slices are identical and the difference is further on. Closes [#1322](https://github.com/reticlehq/reticle/issues/1322).
