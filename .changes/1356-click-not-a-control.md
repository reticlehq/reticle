### Fixed

- **`@reticlehq/core` + `@reticlehq/browser` — a click that lands on something no user could click no longer reports a clean click.** A `{ text }` target matches any element whose own text contains the value, so `{ text: "Sign in" }` could resolve to a wrapper `div` instead of the button inside it. The click hit the wrapper, the form never submitted, and the act still said `ok: true, dispatched: true, settled: true`. A click or double-click now carries the `CLICK_NOT_A_CONTROL` warning when the element has no interactive role, sits inside no control, `label` or `summary`, carries no `onclick` or `tabindex` on the way up, and has no pointer cursor. The last condition keeps a framework `<div onClick>` quiet. The click is not retargeted to the control inside, because that would be a guess. Closes [#1356](https://github.com/reticlehq/reticle/issues/1356).
