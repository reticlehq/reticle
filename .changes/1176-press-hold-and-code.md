### Fixed

- **`@reticlehq/server` — a held key now holds, and a physical `code` is no longer sent to a driver that cannot send one.** A `press` with `holdMs` was dropped by the real-input path: the driver sent an instant down/up and reported success, so a hold-to-confirm control driven through `reticle drive` never held, while the identical gesture on the in-page path worked. `holdMs` now splits the chord into down / wait / up, and the same bounded cap (`clampHoldMs`, lifted into `core`) applies to both paths so one `holdMs` cannot hold longer through one route than the other. Separately, `press { text: "z", code: "KeyY" }` — a caller on a non-US layout naming the physical key — was forwarded to a driver that presses by KEY name and would have struck a different key than the one asked for; it now stays on the in-page dispatcher with `inputModeReason: "synthetic-key-code-press-preferred"`. Closes [#1176](https://github.com/reticlehq/reticle/issues/1176).
