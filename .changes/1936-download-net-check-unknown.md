### Fixed

- **`@reticlehq/engine` — a `net` check on a click that downloads a file gave `no`.** A click on `<a download>`, or on a link that the server answers with `Content-Disposition: attachment`, is recorded as a navigation request that stays pending. The browser gives the response to its download manager, so the page never sees the status. A check such as `until: { net: { status: 200 } }` found no completed call and failed with "no matching call", while the browser saved the file. Now a `net` check that matches no completed call, in a window that holds a navigation record for the same method and URL, is `inconclusive`. The reason says that the request went to a download or a document navigation and that the net channel cannot see its result. Before, this applied only when the filter's URL ended in a file suffix such as `.pdf`. Closes [#1936](https://github.com/reticlehq/reticle/issues/1936).
