### Fixed

- **`@reticlehq/engine` — one clause that could not be read made the whole `allOf` or `anyOf` `unknown`.** A check expected `POST /api/auth/login` to answer 401, and it answered 500. A text clause in the same `allOf` timed out on a slow page. The verdict was `unknown`, with "the page did not answer: command 'match' timed out", and the 500 was lost. The cause: `allOf` and `anyOf` read their clauses together, and one read that threw rejected all of them. Now a clause whose read throws is inconclusive by itself, and it keeps the read's error message. The composite rules then decide. In `allOf`, a clause that failed outranks a clause that nobody could read, so this check is `no` at the end of the budget. In `anyOf`, a clause that passed is a pass. A `not` of an `allOf` that failed is a pass. When no clause gives an answer, the result is still `unknown`, with the read's error message. No timing rule changes. Closes [#1656](https://github.com/reticlehq/reticle/issues/1656).

  What changes for each caller of a composite check:
  - **The wait** (`reticle_act_and_wait`, `reticle_assert` with a budget, a step of `reticle_act` with `steps`, the reload check of `durable`). A composite that is `unknown` because a read threw still ends the wait at once, as before. A composite with a clause that failed waits to the end of the budget and gives `no`. Before, it ended at once with `unknown`.
  - **A one-shot check** (`timeout_ms: 0`). Before, a read that threw gave a tool error. Now it gives a verdict. When no clause gives an answer, the verdict is `unknown`, and its reason includes the read's error message.
  - **The check before the action** (`already_true`). A read that threw still stops the call with the read's error, as before. Reticle cannot tell whether the consequence was already true, so it does not run the action. An `allOf` with a clause that failed is not already true, so the action runs.
  - **The revert check after a match** and **the second read of a match on a hidden element**. These read the page after the action. Before, a read that threw gave a tool error. Now it gives a verdict: an inconclusive read is "not reverted" and keeps the first verdict, and a readable clause that now fails reports the revert.
