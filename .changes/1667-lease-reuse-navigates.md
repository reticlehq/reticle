### Fixed

- **`@reticlehq/server` — re-acquiring a held lease answered with the requested url while the tab stayed on its old page.** `reticle_lease { action: "acquire" }` on an origin the caller already holds reused the lease and returned the url it was asked for, but did not move the tab, so the next read was of whatever page the last call left it on. A reused lease on another page is now navigated to the requested url, and the answer waits for its SDK to come back there, as a new lease does. The result carries `navigated: true`. If the tab cannot be moved, `navigated` is `false` and `url` is the page it is on. If it moved but its SDK does not reconnect in time, `ready` is `false` with `sdk_never_dialled`. Closes [#1667](https://github.com/reticlehq/reticle/issues/1667).
