### Changed

- **`@reticlehq/server` — the first `reticle_session` call no longer runs `init` by itself.** In a project that was never wired, an agent that only listed sessions changed `package.json`, the lockfile and the build config, and started a second dev server, which the user did not ask for. The call now changes no file. Its `next_step` names the zero-install lease, which checks the running app now with nothing installed, and the consent question for `init`. The agent runs `init` only when the user agrees. The MCP instructions, `SKILL.md`, the docs and the Claude Code plugin say the same thing, and the plugin now leads with the lease. `reticle init`, `reticle connect` and a setup request from the user still wire the app as before. The `wired` field is gone from the session list.
