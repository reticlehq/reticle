### Fixed

- **`@reticlehq/server` — a CI job with only `RETICLE_API_KEY` set now syncs.** A committed `.reticle/cloud.json` makes a CI clone a linked repo, and the key was read only from `~/.reticle/credentials.json`, which CI does not have; an unlinked repo, the harness and the platform settings also needed a URL. The environment key is now used when no stored key exists, and the URL defaults to `https://app.reticle.sh`. A stored key still wins, and an environment key is only sent to its own host.
- **`@reticlehq/server` — what the platform refuses is now reported.** A refused flow, capsule or derived record counted as sent, and the cycle reported success. `reticle push` now lists every refusal and exits `1`, `reticle whoami` keeps the reason as `lastError`, and the background daemon logs it.
- **`@reticlehq/server` — sync no longer re-uploads records an older platform does not know.** A record kind the platform does not list, and a flow or run in a file version it does not read, is held back and named once instead of being re-sent with every flow on every cycle. Runs also go up in bounded batches, so a large backlog is no longer refused as one oversized request.
- **`@reticlehq/server` — a run the platform refused is no longer offered on every cycle.** It is remembered with the reason, and offered again only when the run file changes or the platform reports that it reads more. Until then `reticle push` and `reticle whoami` show it as `refused, not retried`, and it no longer keeps the background sync on its fast interval.
- **`@reticlehq/server` — `reticle verify`, `reticle_project` and the harness read the key `reticle link` stored.** They read only the environment, or let an exported key win over the stored one. Every caller now uses the stored key for the linked host first and the exported key second.
