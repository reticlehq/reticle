### Fixed

- **`@reticlehq/server`, `@reticlehq/browser`: `reticle_session` tune action branches error advice on SDK version and session ID.** When `tune` fails to apply HUD positioning or visibility changes, the advice previously assumed the page SDK predated the feature (`the page did not apply 'hud': its Reticle SDK predates it, or no HUD is mounted...`). The daemon now inspects `session.sdkVersion` and branches advice: advising SDK upgrade if < 3.6.0, diagnosing that no HUD is mounted on that session if >= 3.6.0, and explaining that the HUD was removed and needs a page reload to restore when the page explicitly answered with `reload to restore`, with all diagnostic messages identifying the session ID. Presenter also returns explicit `reload to restore` feedback when `placeHud` is called after being removed. Closes [#1557](https://github.com/reticlehq/reticle/issues/1557).
