### Fixed

- **Installing and connecting, as written.** The install docs were checked end to end against the published 3.6.0, and every instruction that did not work as written now does:
  - **Hand-wired `connect()` (blocker).** The hand-wired `connect()` examples in the manual install and getting-started pages had no pairing token, so on any stack without the Vite or Next plugin the bridge refused the page and no session ever connected. They now pass the token, say where it comes from, and point first at `reticle init`, which wires every supported stack (plain HTML included) without the token reaching anything you ship.
  - **Windows installer.** `install.ps1` no longer stops at the first line npm writes to stderr on Windows PowerShell 5.1. It calls `npm.cmd` and `reticle.cmd`, so the default script execution policy does not block it. Under `irm … | iex` it no longer closes your PowerShell window on success or failure.
  - **macOS and Linux installer.** `install.sh` now prints why agent registration failed, instead of exiting with only a code.
  - **README example.** The README's main `reticle_assert` example (`{ allOf: [...] }`) did not parse; it is now `{ kind: "allOf", predicates: [...] }`.
  - **Agent-facing messages.** Asking for `reticle_verify { action: "explore" }` on an unlinked project no longer tells the agent its call was invalid; it says to link the project or drive the journey itself. `reticle_tools` no longer lists `reticle_assert` and `reticle_observe` as retired. The no-session text from `reticle status` and one refusal named the retired `reticle_sessions`; both now say `reticle_session { action: "list" }`.
  - **Docs no longer describe pre-3.6 behaviour.** The Harness drives only on the platform, and the docs now say explore needs `reticle connect` and that a free account is created in the browser. They also give the Node floor (20.11), the tool counts, what `init` writes, the Codex config path, and when a project is wired automatically (the first session call in that project).
