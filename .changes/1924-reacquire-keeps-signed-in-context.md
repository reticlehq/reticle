### Fixed

- **`@reticlehq/server` — acquiring a lease again closed the signed-in tab and opened a signed-out one.** When the first `reticle_lease { action: "acquire" }` answered `ready: false`, a second acquire on the same origin released that lease and opened a new browser context. The new context had no cookies, so an agent that had signed in lost the sign-in and could not retry without signing in again. Now the second acquire loads the page again in the same context and waits for it to connect. If it still does not connect, or the page does not load because the app is restarting, the lease is kept and the answer says so, with `reused: true`. A tab that was closed is still released and replaced by a new one. Closes [#1924](https://github.com/reticlehq/reticle/issues/1924).
