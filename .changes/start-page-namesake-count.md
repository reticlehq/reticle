### Fixed

- **`@reticlehq/server` — replay goes to a flow's start page when the current page only has controls of the same name.** Before step 1, replay stays on the current page when the first step can already start there. It decided that when the step's control name matched anything, so a flow recorded on a tags page ("Edit", 1 of 10) stayed on a bookmarks page with 30 links named "Edit", and then stopped as ambiguous: a working app replayed `unknown`. A role and a name on another page do not say which control they are, even when the count is the same: a flow recorded on a tags page started with a click on button "Search", stayed on a bookmarks page that has its own "Search", and searched the wrong list. Replay now stays only for a control that the app names itself (a testid or a component). Otherwise it goes to the start page.
