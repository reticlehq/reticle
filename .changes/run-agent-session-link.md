### Changed

- **`@reticlehq/core`, `@reticlehq/server` — a run joins its agent session by id, not by "newest".** With two agents in one project, a run written outside a call (a session's end) took the newest episode in the project, and its model and closing claim came from the first stop of any session of that agent. The agent's MCP server now announces the agent's own session id on connect (Claude Code's `CLAUDE_CODE_SESSION_ID`, the `session_id` its hooks receive), and the episode's start record keeps it. A run is stamped with `agentSession` and with the episode of the calling connection, or, outside a call, the episode whose calls last drove the run's tab, or the project's only episode; otherwise nothing, never a guess. The model and closing claim are read from that session's `agent-<session>.jsonl` only; a run with no session reads the agent's records by name only when they all come from one session.
