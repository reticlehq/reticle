### Fixed

- **`@reticlehq/server` — the session list reported a daemon split to a port the project used before.** After `.reticle.json` moved a project to a new port, the daemon on the old port could still be alive and remember a session. With no app connected, the session list, `reticle status` and `reticle doctor` then said the app was on the old daemon and told the agent to move there and restart. The page dials the configured port, so a lease on the current URL connected and verified on this daemon. Reticle now reports no split when the configured port is this daemon's port and the page's own port rule picks it. `reticle status` and `reticle doctor` also take the configured port as the project's own daemon, so they no longer call that daemon a stranger and ask for a restart. The no-session answer also no longer offers a live Reticle daemon's port as a process that could be the app. Closes [#2341](https://github.com/reticlehq/reticle/issues/2341).
