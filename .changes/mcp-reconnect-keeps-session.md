### Fixed

- **`@reticlehq/server` — one short drop of the MCP link ended the browser session and could close the agent's MCP server.** When the proxy reconnected to the daemon, the daemon saw a new agent. It ended every browser session, so the agent's next call answered "no connected session", and the agent lost its leased tab. Now each proxy sends a fixed id on every connect. A proxy that comes back keeps its identity, its leases and its tab. The daemon also waits 10 seconds after the last agent detaches before it ends the sessions. Separately, resets on the proxy's own sockets to the daemon no longer count as the client going away, so the proxy does not exit while the daemon is healthy.
- **`@reticlehq/server` — telemetry can now tell a reset of a live stream from a refused connect.** A reset reports `sse_reset` with its error code, not `connect_error`. Three new events report when the MCP proxy exits and why (`mcp_proxy_exited`), when a daemon died without a clean stop (`daemon_died_unclean`), and when a wake was refused because something else held the port (`wake_refused`). No event carries a path, a port or a message. See `docs/telemetry.md`.
