### Fixed

- **Checking a controlled checkbox was graded `state-vs-render` even though the box checked.** React sets `checked` and `value` as properties, so the rule that the store committed and nothing rendered never saw the screen move, and `act_and_wait` came back `verified: "unknown"`. A field the app itself wrote during the action (as React does when it commits a controlled input) now counts as the screen moving when its value after the handlers differs from the value before the action. The browser's own toggle or keystroke does not, so an uncontrolled field whose component never re-renders still reports the contradiction, and so does a control restored to its previous value. Checkbox and radio field events carry `checked`. Closes [#1357](https://github.com/reticlehq/reticle/issues/1357).
