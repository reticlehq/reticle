### Added

- **`@reticlehq/server`: every command that opens a browser reads `--ignore-https-errors`.** A dev server on `https://` with a self-signed or mkcert certificate made `reticle serve --drive`, `reticle drive` and `reticle verify` fail with `net::ERR_CERT_AUTHORITY_INVALID`, and the only way out was the MCP tool: `reticle_lease { ignoreHTTPSErrors: true }`, which is no use to somebody running a shell command because their client has no Reticle tools at all. `serve`, `mcp` and `_daemon` now set it for every browser the daemon opens, so every lease inherits it. `drive` sets it on the browser it opens, and forwards it with the attach request so a daemon that was started without the flag still opens the tab for that run. `verify` sets it on the browser it opens, and refuses, naming the flag, when a daemon already owns the port and its browser is the one that would load the page. A navigation that the certificate stopped now names the flag when it was not passed. Closes [#1713](https://github.com/reticlehq/reticle/issues/1713).
