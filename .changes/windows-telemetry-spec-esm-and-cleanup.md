### Fixed

- **`telemetry-events-test` could not run at all on Windows, for two separate reasons.** It built `DIST`/`ENGINE_DIST` as filesystem paths and then used them as the base of a dynamic `import()`, which on Windows throws `ERR_UNSUPPORTED_ESM_URL_SCHEME` — _"absolute paths must be valid file:// URLs"_ — so the spec died before a single check ran. Both are now `file://` URLs, the way the `core` import a few lines below already did it. With that fixed the spec reached **149/149 checks** and then failed anyway, on `rmSync` of its scratch directory: `force: true` only swallows "it was not there", and Windows returns `EPERM` while any handle in the tree is still open. Cleanup now asks for the retry behaviour Node documents for exactly that case (`maxRetries`/`retryDelay`, which back off on `EPERM`/`EBUSY`) and, if it still cannot delete, says so and carries on — the spec exists to prove telemetry events reach the wire, and a 149/149 run reported as FAILED because of a locked temp file is a false red. The gate that exists to catch telemetry going missing silently had itself been silently absent on Windows.
