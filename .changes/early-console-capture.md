### Fixed

- **`@reticlehq/server` — a console error that a page logged while it loaded was lost.** An app connects the SDK from a module script or a bundle, and those run after the page's own scripts. An error that such a script logged during the load came before the SDK, so "no console errors" passed on a page that logged an error on every load. A page that Reticle drives (a leased tab, and the page `reticle verify` opens) now keeps its console errors, warnings and error events from the first script. When the SDK has installed, the page sends them through the console and dispatches the events again, so the SDK reports them with its usual handlers. The SDK has no extra code for this, so a page that Reticle does not drive downloads nothing more. The queue holds 200 entries. When it overflows, one console warning says how many entries were not kept.
