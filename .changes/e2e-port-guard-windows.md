### Fixed

- **The e2e battery's port guard did nothing on Windows, which is where it was most needed.** `run-ci.sh` waits for its ports before booting, so a back-to-back run cannot start on the previous run's teardown — the comment above it records losing "a whole 8-minute run lost to the run before it" twice in one afternoon. It asked `lsof`, which does not exist on Windows, and the shape it was written in turned that into silence rather than noise: a missing command exits non-zero, so `lsof … || break` concluded "free" on its first poll, and the `if` beneath it failed the same way, so the refusal never printed. The battery then booted onto an occupied port and died on a raw `EADDRINUSE` stack — or, worse, ran against **another process's app** and reported on it, which is the exact outcome the guard exists to prevent. The wait now goes through `await-free-ports.mjs`, which asks the netstat-backed `pidOnPort` that `gate-harness.mjs` already reaches for on win32 (its own comment: _"Windows has no lsof, and `lsof()` answers 'nothing matched' for a tool that is absent — an honest answer to the wrong question"_). Verified on Windows 11: a free port passes immediately, and a held one is refused after the same 30s wait, now naming the pid that holds it.
