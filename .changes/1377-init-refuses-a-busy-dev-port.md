### Fixed

- **`@reticlehq/server`: `init` no longer starts a dev server beside one that holds only half of its port.** With a Docker or nginx stack on 5173, `init` ran `pnpm dev`. On macOS, Vite can bind `[::1]` beside a process holding `0.0.0.0:5173` and print nothing, so `localhost:5173` and `127.0.0.1:5173` served two different apps and the SDK seemed to connect at random. Before spawning the dev script, setup now asks both loopbacks whether anything answers on the dev port. When something answers on one and nothing on the other, setup stops, names both addresses, and offers `--url` to attach or another port. A port busy on both loopbacks, such as a second Vite app on 5173, starts as before: the dev server sees it, moves to the next port, and setup reads that. The port is the one the script pins, else the framework's default from `@reticlehq/init`'s dev-server port table; when a dev config sets its own port, nothing is guessed and nothing is probed. Closes [#1377](https://github.com/reticlehq/reticle/issues/1377).
