### Added

- **`@reticlehq/server`, `@reticlehq/core`, `@reticlehq/browser`: telemetry says who is signed in, which agent asked, which HUD page was used, and how a Harness run went.** Four new event kinds, each with closed-set properties only: `hud_viewed` (a HUD page or the account menu opened, deduped per tab), `hud_signin_prompted` (a sign-in or link prompt was shown, once per surface per tab), `platform_linked` (a project was bound to a workspace, and how) and `harness_run` (one `started` and one `completed` per run, with its source, outcome and journey buckets). Every event now carries `accountState` (`signed_out` / `signed_in` / `linked`), `linked`, the linked workspace's `workspaceId` (never its name, never an email), the coding agent as a closed `client` value, and `launch` (`npx` / `global` / `project` / `other`). The approval page a sign-in opens carries `from=terminal` or `from=hud`. The one-line installers declare `installSource: install_script`, and a declared install channel is remembered on the machine so later commands carry it. Documented in `docs/telemetry.md`, `docs/telemetry-contract.md` and `docs/telemetry-events.mdx`.

### Fixed

- **`@reticlehq/browser`, `@reticlehq/server`: the HUD's Harness page and account menu are counted as themselves, and HUD time stops when nobody can see it.** The Harness page was timed as the Agent Log it opens over, and the account menu was not seen at all. HUD view and page time is now kept per tab and pauses while the tab is hidden or gone; two tabs used to share one clock and a background tab kept accruing.
- **`@reticlehq/server`: the `automation` hint no longer reports `no_tty` for every MCP server.** An MCP stdio process never has a terminal, so the hint fired on almost every event and separated nothing. It now reads only declared markers: a hosted agent sandbox, a CI vendor's own variable, a container, a hosted workspace.
