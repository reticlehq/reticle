### Fixed

- **`@reticlehq/server`: runs that never reached the dashboard.** Runs written into a folder with no link were skipped without a word, drives on a browser Reticle opened were filed under `~/.reticle/unmatched` where nothing syncs them, and `reticle link` could bind a different folder from the one runs were written to. Leased, `try`, chat and Harness sessions now write into the project of whoever started them, `reticle link` binds the folder runs actually land in, and a folder holding runs that were never sent is named — in `reticle sync`, `reticle doctor` and the HUD — with the command that sends them. A run push no longer re-sends every saved flow (about a megabyte each time) unless the flows changed. `verify` and `try` print the run's dashboard link, and `reticle runs <id>` reads a run back from the platform.
