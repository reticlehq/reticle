### Fixed

- **`@reticlehq/server` — in a fresh sandbox, the agent waited for a download before Reticle started.** `reticle init` and `reticle setup mcp` registered `npx @reticlehq/server mcp`. With an empty npm cache, npx downloaded the package at each boot before the MCP server answered: 3.9 s to 5.6 s and about 131 MB, against 0.6 s warm. When the CLI is installed (globally or in the project), the registration now starts that copy with `node <path>/bin/reticle.js mcp`. Without an install, it names one exact version, so an image with a filled npm cache uses it again. A re-run replaces an older npx entry of our own in the agents whose config Reticle writes. When the installed copy is removed later, `reticle doctor` prints a `launcher` row with the missing path and the command to run. For sandbox and container images, install the CLI once in the image: `npm install -g @reticlehq/server`.
