### Fixed

- **`@reticlehq/server` — a session's `events.jsonl` can no longer grow without bound, or reopen after it stops.** Nothing capped the per-session event ledger, so an app emitting a repeating uncaught error wrote `.reticle/sessions/<id>/events.jsonl` at loop speed until the disk was full — `pruneSessions` bounds how many session directories survive and has never had an opinion about how big one of them is. Each ledger now stops at 64 MiB: the batch that would cross the ceiling is refused whole (never split into a half-written line), nothing already on disk is deleted or rotated away, and the refusal is recorded beside the file so it survives a reload. That last part is the whole bound — a session id lives in `sessionStorage`, so the next connection reopens the same ledger, and a ceiling held only in memory is a ceiling per connection. A closed ledger now refuses a one-event batch as firmly as the batch that closed it.

  **The loss is declared twice, because one declaration was not enough.** A `truncated` event naming the `journal` channel is appended as the ledger's last record, so any existing reader sees it. But that record carries a timestamp and every journal-backed query filters on timestamps, so a window opened after the cap was hit contains no marker, no events, and nothing to distinguish it from a window in which nothing happened. A verdict drawn from such a window now comes back `unknown` / `unclean_capture` with the new `journal_loss` kind, instead of a green resting on evidence that was never written. Absence assertions only — a positive assertion that found its evidence is not impeached, and live ring-buffer data is never discarded over this.

  Two smaller repairs ride along. A `stat` that failed for any reason other than "no such file" was read as an empty ledger, which handed the writer a full budget over a file that may already have been at the ceiling — the cap disabled by exactly the conditions most likely to accompany a failing disk. And a batch is now serialized only until it has outgrown the remaining budget, so a runaway session stops paying full serialization cost for writes it will never be allowed to make. Refs [#986](https://github.com/reticlehq/reticle/issues/986).
