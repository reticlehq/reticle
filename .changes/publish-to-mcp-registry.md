### Added

- **A release now publishes to the official MCP Registry, not only to npm.** `server.json` and `mcpName` landed already, but nothing invoked `mcp-publisher`, so the registry entry would have had to be pushed by hand after every release — and a step that is only ever done by hand is a step that is eventually skipped. The publish workflow now runs it after the npm publish, in that order because the registry resolves `server.json`'s version on npm and refuses one that is not there yet. It needs **no new secret**: `mcp-publisher login github-oidc` trades the workflow's own OIDC token for a registry JWT, which is what the job's existing `id-token: write` (added for npm provenance) already provides. The `mcp-publisher` binary is pinned by tag **and** verified by sha256 before it runs, because an unpinned `latest` download would put a third party's new binary into the one job that holds this repository's publish identity.
