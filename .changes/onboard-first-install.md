### Fixed

- **`@reticlehq/server`: the dev server `init` starts no longer dies after `init` exits.** It was spawned with its output piped back to `init`, so the first line it printed once `init` had gone (an HMR update, a compile error, a warning) killed it with nothing logged anywhere: "it connected, then the app went away". Its output now goes to a file under `~/.reticle/`, and `init` prints where.
- **`@reticlehq/server` + `@reticlehq/next`: a Next.js 16 app connects on the first `init`, not only the second.** A cold Turbopack compile outlasted `init`'s five-second page check, which then retried `127.0.0.1` and opened the browser there. Next 16 blocks its dev resources for any origin outside `allowedDevOrigins`, so the page never hydrated and the SDK never dialled. The page check now only changes address when the connection is refused, never on a timeout, and `withReticle` adds the loopback aliases to `allowedDevOrigins` in development (Next 14.2.30+ / 15.2.2+).
- **`@reticlehq/engine`: `open-verification` is declared as a dependency.** It was listed only as a devDependency, so under Yarn PnP or pnpm without hoisting the CLI died on load with "Cannot find package 'open-verification'" (or "tried to access open-verification, but it isn't declared").
- **`@reticlehq/init` + `@reticlehq/vite-plugin` + `@reticlehq/next`: the port lives in one place and everything follows it.** Re-running `init` with a new `--port` used to report success and change nothing; it now moves every port it wrote (`.reticle.json`, the Vite config, Next's `reticle-dev.tsx`, the SvelteKit hook, the Nuxt plugin, a plain page, an Angular entry). The build plugins dial a live daemon registered for the project, then `.reticle.json`, then the plugin option, and say so once when the option and `.reticle.json` disagree. `init` also honours `RETICLE_PORT`, like every other command.
- **`@reticlehq/server`: `init` no longer adopts an older daemon on its port.** A daemon on a different wire contract with no sessions is replaced; one with live sessions stops `init` with the exact command to run.
- **`@reticlehq/server`: the CLI runs the version that matches your project's SDK.** `npx @reticlehq/server` resolves the latest release, so a project still on a 2.x SDK got a 3.x daemon and every verdict came back `version_skew`. When the project's installed SDK is on a different major, the CLI re-runs itself as that version. `init`, `update` and `rollback` are exempt, as is an explicitly pinned version and `RETICLE_NO_VERSION_MATCH=1`.
- **`@reticlehq/server`: a Reticle-owned browser works on a fresh machine.** When Playwright's Chromium is not installed, Reticle uses an installed Google Chrome or Microsoft Edge, and otherwise installs the pinned Chromium itself, instead of refusing with "Chromium is not installed for Playwright".
- **`@reticlehq/server`: `reticle verify <url> --expect` and `--explore` work straight after `init`.** `--expect` used to answer `unknown` when no tab was open and point at another project's dev server; it now opens a Reticle-owned tab on the URL it was given. `--explore` used to refuse because `init` left a daemon running; it now runs on that daemon.
- **`@reticlehq/init`: Remix v2 (Vite), Electron Forge, Angular 17+ and plain HTML are wired, not guessed at.** Remix was detected as plain Vite and never connected; Forge's `vite.renderer.config.*` was not recognised; Angular fell back to HTML, installed the React kit, and offered two snippets that failed (one did not compile, one shipped the pairing token in the production `index.html`). Angular now gets a dev-only connect in its browser entry and a dev-server route for the token, so no secret lands in a project file or a bundle. A plain HTML page gets the snippet written into it.
- **`@reticlehq/init`: Tauri and Electron Forge apps start with their own launcher.** `init` ran the `dev` script, which on the Tauri template is plain Vite, so no window ever opened; it now runs `tauri dev` (or `electron-forge start`).
- **`@reticlehq/vite-plugin`: a production desktop build carries no instrumentation.** With `desktop: true`, `vite build` shipped the whole SDK and a renderer that dialled `ws://localhost:<port>`. Only a non-production mode is instrumented now.
- **`@reticlehq/init`: an Electron CSP that blocks the bridge is patched, not misdiagnosed.** electron-vite's template `default-src 'self'` blocks the WebSocket; `init` reported an inline-script rule that did not apply and then waited ten minutes. It now adds the bridge origin to `connect-src` in the renderer's CSP meta, or stops with the exact line when the policy lives somewhere it cannot edit.
- **`@reticlehq/init`: monorepos.** A backend with a `dev` script no longer blocks `init` at the root; re-running at the root after `--app` uses the app the root config already names; running inside an app writes the same root pointer `--app` does, so an agent opened at the repo root finds it. From the root, the CLI reads the port of the one app wired below it instead of falling back to `:4400`.
- **`@reticlehq/init`: `reticle-dev.ts` runs on every framework that gets one.** On SvelteKit and TanStack Start it was written and never imported, so stores and capabilities registered there silently did nothing. TanStack Start is now wired by `init` instead of left as a manual step.
- **`@reticlehq/init`: generated code typechecks.** React Router framework mode's `npm run typecheck` went red on `import('/@reticle-connect')`; the printed Vite config forgot to import `defineConfig`; TanStack Start's recipe referenced an undeclared `__RETICLE_TOKEN__`. The store hints name stores that exist in your code rather than a placeholder `cartStore`.
- **`@reticlehq/server` + `@reticlehq/vite-plugin`: fewer diagnoses that send you the wrong way.** "SDK is NOT in the page … restart the dev server" is no longer printed for frameworks that connect from the JS bundle (SvelteKit, Nuxt, React Router, Remix, TanStack Start, Angular, Next), and the plugin no longer warns "this app will never connect" about a page that connected through `/@reticle-connect`.
- **`@reticlehq/server`: desktop projects get desktop advice.** `reticle doctor` no longer reports a missing capture helper in a bundled Electron main process, and the no-session guidance tells a desktop project to run its desktop dev command instead of opening a URL.
