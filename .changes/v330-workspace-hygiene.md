### Fixed

- **`@reticlehq/server` — the only bound that limits SIZE was never called.** Retention wired three count bounds and not the byte budget, which had been written and tested and had no callers. A count says how many session directories are kept and nothing about how large one may get, so a single chatty drive could grow a workspace without tripping anything. It now runs, and it runs in the workspace the session actually wrote to rather than only the daemon's own — for a globally registered daemon those are different directories, and the per-project one is where the bytes accumulate.

- **`@reticlehq/server` — visual diffs and feedback copies were swept in the wrong tree.** Session teardown pruned journals at the session's own root and left the other tiers to a daemon-start sweep of the daemon's root. The two tiers that only ever grow inside a project workspace were the two never pruned there.

- **`@reticlehq/server` — a session nobody drove kept a full journal.** Observers run from the moment the SDK attaches, so an idle tab on a busy page accumulates a journal without a single tool call, and those directories occupy retention slots — evicting journals that could answer a verdict question in favour of ones that were never asked one. Such a journal is now dropped at teardown. Capture is unchanged: whether a tool call will happen is not knowable while the events that would answer it are being recorded.

- **`@reticlehq/server` — route statistics never accumulated on apps with ids in their URLs.** Deviation envelopes were keyed on the raw pathname, so `/orders/1001` and `/orders/1002` were different baselines and every visit created one holding a single sample. Nothing ever reached the minimum sample count, so the deviation report answered "envelope too new" permanently and the feature never turned on. Envelopes are now keyed on the route template. Collapsing is conservative — only all-digit, uuid and long-hex segments — because merging two genuinely different routes into one baseline is the more expensive mistake.

- **`@reticlehq/server` — two daemons on one repository raced on the same temporary file.** Five stores wrote their atomic-rename temp file under a name derived from the destination, which every writer of that path shares. Running parallel agent sessions against one checkout is the ordinary way to reach that: one truncates the other mid-write and renames the remains into place. The temp name now belongs to the writer, and to the individual write.
