### Fixed

- **`@reticlehq/engine` — `response-ignored` missed an app that ignored its response when the clicked button changed `disabled` or `aria-busy` while the request ran.** The change counted as the client answering the write, so a 2xx that changed nothing else on screen gave `verified: clean`. The acted control becoming disabled or busy after the write was sent, or changing either attribute before the send, no longer counts as an answer. Taking the control out of that state still counts wherever it is, so a settings form that enables Save again in its response handler is not accused, over fetch or XHR. Every other change still counts, so an optimistic update is not accused. Two limits: a button that only becomes disabled after the response is reported, and a label such as "Saving…" still counts as an answer. Closes [#2115](https://github.com/reticlehq/reticle/issues/2115).
