### Fixed

- **`@reticlehq/server`, `@reticlehq/react` — flow replay clicked a server-rendered button before React hydrated it.** On a Next.js page with a slow Suspense boundary, the SDK connects before the boundary has event handlers. Step 1 clicked the button, nothing happened, and the flow failed on a correct app. Replay now waits before step 1 until the React adapter says that the page is hydrated, for at most 10 seconds. When the wait reaches that bound, the replay result carries `hydrationWait: { waitedMs, budgetMs }`. A page without `@reticlehq/react` does not wait. The adapter now also fires `reticle:hydration-complete` when React hydrated the page before `install()` ran, and it waits for every dehydrated Suspense boundary, not only the first commit. Closes [#1654](https://github.com/reticlehq/reticle/issues/1654).
