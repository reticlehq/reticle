### Changed

- **`@reticlehq/server` — a verdict answers in a few hundred tokens, not a few thousand.** `reticle_act_and_wait`, `reticle_assert` and `reticle_act { steps }` now return a compact envelope by default: the verdict, `because`, the deciding evidence (transport detail such as initiator stacks removed), expected/observed, contradictions, capture integrity, failed requests and console errors, the acted `ref` and `source` file:line, the screenshot path, the cursor, and one `changed` line naming the route, requests, state paths, storage keys and signals that moved. Trace counts, state-diff bodies and layout metrics are one `detail: "full"` (or one `reticle_observe { since }`) away. A property test fails the build if compaction ever drops a decisive field.
- **Cache bookkeeping no longer reads as a state change.** A query cache moving only `fetchStatus`, `isStale`, `dataUpdatedAt` or `status` is counted (`ignoredBookkeeping`) instead of listed in `stateDiffs`; a change to `data` or `error` is always reported. Predicates still see every transition.
