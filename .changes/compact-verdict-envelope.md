### Changed

- **`@reticlehq/server` — a verdict can answer in a few hundred tokens, on request.** `reticle_act_and_wait`, `reticle_assert` and `reticle_act { steps }` accept `detail: "compact"`: the verdict, `because`, the deciding evidence (transport detail such as initiator stacks removed), expected/observed, contradictions, capture integrity, failed requests and console errors, the acted `ref` and `source` file:line, the screenshot path, the cursor, and one `changed` line naming the route, requests, state paths, storage keys and signals that moved. Trace counts, state-diff bodies and layout metrics are left out. The full envelope stays the default: in the agent-loop benchmark the compact arm was not at least as accurate as the full one, and a token saving ships only beside a correctness measurement that is. A property test fails the build if compaction ever drops a decisive field.
- **Cache bookkeeping no longer reads as a state change.** A query cache moving only `fetchStatus`, `isStale`, `dataUpdatedAt` or `status` is counted (`ignoredBookkeeping`) instead of listed in `stateDiffs`; a change to `data` or `error` is always reported. Predicates still see every transition.
- **`RETICLE_RESULT_DETAIL=compact`** on the daemon makes every agent call answer compact unless it asks for `detail: "full"`; `RETICLE_RESULT_DETAIL=full` answers in the full envelope without notices, the control arm for measuring the two on the same build.
