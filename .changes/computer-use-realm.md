### Added

- **`@reticlehq/server` — a desktop application can join the bridge with no SDK in it.** A realm that reads an application through the operating system joins as a peer, and the tools for a web page then work on it. The Harness (`reticle_verify { action: "explore" }`) gets a prompt for a desktop application: it sends the model to a file, a setting and the clipboard, not to a link or a request. The realm package (`@reticlehq/computer-use`, macOS) is in the repository and is not published yet. It reads an application through the accessibility tree, acts in the background, and, when a caller asks with `args.foreground: true`, uses the real pointer for a double-click, a hover, a drag and the menu bar. For an application with no elements it gives a picture of the window to `reticle_screenshot` and acts at a point of it. A text that takes no click, as the display of Calculator, is visible when the system gives the area that holds it as the answer of a hit test. The join sets the accessibility switch for a Chromium browser too, with the second switch that Chrome needs before a press reaches its page. It reads and scrolls a page in Safari and in Chrome; a page with no scroll bar is scrolled with a key. When a desktop application and an app with the SDK are both connected, `reticle_session { action: "list" }` gives a `realms` field that says which session to use for what. Its `samePage` names a window of the desktop session that shows the page of an SDK session, matched by title.

### Changed

- **`@reticlehq/engine` — a signal that an observer saw is evidence for a session with no SDK.** The rule `signal-without-consequence` is for a signal that the application sends about itself. A session of a peer realm has no SDK, so each of its signals is a thing the realm saw from outside: a file that was written, a setting that changed. An action whose only effect is such a signal now gets `yes`. A session with an SDK is judged as before.
