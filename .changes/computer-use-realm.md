### Added

- **`@reticlehq/server` — a desktop application can join the bridge with no SDK in it.** A realm that reads an application through the operating system joins as a peer, and the tools for a web page then work on it. The Harness (`reticle_verify { action: "explore" }`) gets a prompt for a desktop application: it sends the model to a file, a setting and the clipboard, not to a link or a request. The realm package (`@reticlehq/computer-use`, macOS) is in the repository and is not published yet. It reads an application through the accessibility tree, acts in the background, and, when a caller asks with `args.foreground: true`, uses the real pointer for a double-click, a hover, a drag and the menu bar. For an application with no elements it gives a picture of the window to `reticle_screenshot` and acts at a point of it. A text that takes no click, as the display of Calculator, is visible when the system gives the area that holds it as the answer of a hit test. The join sets the accessibility switch for a Chromium browser too, with the second switch that Chrome needs before a press reaches its page. A ref goes with a field that the application moves in its tree when the field takes a value, as the search field of Dictionary. The three buttons at the top of a window have names (`Close window`, `Minimize window`, `Zoom window`), from what the system says they are. An item of a list (a group with no name, beside twins of the same shape) is known by its words and not by its place, so a row that comes above it does not give its ref to another row. It reads and scrolls a page in Safari and in Chrome; a page with no scroll bar is scrolled with a key. When a desktop application and an app with the SDK are both connected, `reticle_session { action: "list" }` gives a `realms` field that says which session to use for what. Its `samePage` names a window of the desktop session that shows the page of an SDK session, matched by title. A click or a hover at a point of the picture goes to that point: the middle of the element of the ref can be under another view, as the middle of Dia's window is under its sidebar. A point on a part of a window that gives no element, as the pinned tabs of Dia, is accepted when the window in front at that point is the application's own. A radio button and a menu item with the value 1 say `checked`, so the current tab of a sidebar and the current profile of a switcher are known. A press with no key in `args.text` is refused with a message that says where the key goes, in place of the helper's "unknown-key". `reticle_screenshot { screen: true }` takes the whole display that holds a desktop application, with every application on it: an overlay of another application, or a dialog of the system, is in the picture. A click at a point of that picture goes to that point of the screen. A session with no desktop realm says that it cannot take the screen, and gives no picture of a page in its place. The HUD of a desktop session shows the person's turn: `reticle_session { action: "yield", mode: "ask", note }` opens it with "Your turn: <note>", and its Pause button becomes "Done". "Done" reaches the agent as the person's message (`reticle_messages`), for a 2FA code or a captcha in the middle of a task. The Dock is visible: its application gives the size 0 and has no window, and that size hid every item in it. A list of a Chromium page that gives no visible rows (the list of servers in Discord) shows its rows. `scroll` with `args.foreground: true` turns the real wheel over the element, for a list of a web view that has no scroll bar and takes no key. While a desktop session is live, the pointer of the HUD is on the screen: black with an edge of orange and blue that moves round it. It goes to each control the realm presses, and to the point of a click at a point of a picture. A button under an empty layer that clicks go through (Discord keeps one over its whole window for popups) is not refused as covered: Chromium names that layer in its hit test. A button behind the backdrop of an open dialog is still refused. The windows of the HUD are no longer named as the window over a target. A button behind a popup that has no mark of a dialog is refused too: the popup is drawn after its backdrop. A new action, `window`, arranges the window of an element: `{ arrange: "left" | "right" | "zoom" | "minimize" | "fullscreen" | "restore" }` or `{ frame: { x, y, width, height } }`. It puts two windows side by side, fills the screen, sends a window to the Dock and brings it back (from the application element, as from its tile in the Dock). The answer gives the window after the change, with `minimized` and `fullscreen`, and the action fails when the window is not as asked: an application with no tile in the Dock says yes to minimize and keeps its window on the screen. A page refuses `window`. A point of a picture is now `args.point` (it was `args.at`), and `at` and `to` are fractions of the element's box in a desktop session too, as in a page. A drag ends on another element with `toRef` (as in a page), at a point of the picture with `toPoint`, or at a point of its own box with `to`; it starts at `point` or `at`, so a drag can go from one point of the picture to another, as a window is moved in Mission Control. `scroll` with `point` and `foreground` turns the wheel at that point. A page refuses `point` and `toPoint` and says why: it ignored them before, and acted at the middle of the element.

### Changed

- **`@reticlehq/engine` — a signal that an observer saw is evidence for a session with no SDK.** The rule `signal-without-consequence` is for a signal that the application sends about itself. A session of a peer realm has no SDK, so each of its signals is a thing the realm saw from outside: a file that was written, a setting that changed. An action whose only effect is such a signal now gets `yes`. A session with an SDK is judged as before.
