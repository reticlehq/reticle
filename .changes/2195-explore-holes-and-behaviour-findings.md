### Added

- **`@reticlehq/server` — `reticle_coverage { app: true }` names every hole.** The report has a new `holes` block. It names each route never visited, each control never driven, each control whose edge cases were never driven, each write whose failure path was never driven, and each app function that never ran. A kind that nothing could measure says `measured: false` and tells you why, so an empty list never means "unknown". A list past its cap gives the count of the items it does not name. The report also lists the behaviour faults in the coverage ledger under `findings`. Each finding has the steps that show it and, when the app gives source attribution, the `file:line` of the element. The new finding kinds are `undo-not-restored`, `repeat-changed-state`, `lost-after-reload`, `shown-differs-from-sent`, `intermittent-result` and `failure-unhandled`. Closes [#2195](https://github.com/reticlehq/reticle/issues/2195).
