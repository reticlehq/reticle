### Fixed

- **`@reticlehq/engine` — one click that loads two panels from one route no longer gives a false `no`.** A nav click opened a page that read one path twice in parallel with different filter values (`?businessType=A` and `?businessType=B`), one read per panel. When the first answer arrived last, the window was reported as `stale-response-applied`. A window opened by one discrete action (click, double click, select, check, uncheck, submit) holds no second intent, so two reads after it are panels that the action loaded, not a filter that changed. These windows are no longer checked for that race. Windows with no action and text entry (`type`) keep the check. Known limit: one click whose effect reads with an old value and then the new one is not reported in such a window.
