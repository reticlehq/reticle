### Fixed

- **`@reticlehq/server` — a recorded "this element is gone" no longer replays as "this element is here".** An `act_and_wait { until: { kind: "element", …, absent: true } }` that had answered `verified: "yes"` was saved as an element-PRESENCE expectation, because `FlowExpect.element` had no way to spell the polarity. The replay of that flow then asserted the opposite of what the agent proved: green on the broken app the step was recorded to catch, red on the app working correctly — and graded `presence-only`, so the file looked like somebody had checked. `absent` is now carried from the predicate into the saved step, kept by the replay filter, and compiled back into an absence (gated on settle, exactly as `console.absent` and `text.absent` already are); the two replay paths that answer "present, or drift" — the testid step runner and the `act_sequence` sub-step runner — leave a negative expectation to the predicate engine instead of inverting it.

  An absence that cannot be carried _whole_ is now refused rather than widened. Dropping a narrowing clause from "X is here" leaves a weaker claim; dropping it from "X is NOT here" leaves a stronger one, so `{ role: "button", name: "Remove", scope: "#row-2", absent: true }` would have been saved as "no Remove button anywhere" and failed on a healthy page. The step records no expectation instead, and a flow file that hand-writes one gets a parse error naming the clause that could not be carried rather than a list of predicate kinds it never used. Refs [#988](https://github.com/reticlehq/reticle/issues/988) — that issue collects several independent recorder defects and the rest are untouched here.
