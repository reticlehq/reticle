### Added

- **`@reticlehq/core`, `@reticlehq/engine`, `@reticlehq/browser`, `@reticlehq/server` — a `text` check can ask for an exact number of copies with `count`.** A chat that repeats one heading in every answer already showed it once, so `{ kind: "text", contains: "Answer" }` was true before the action and `act_and_wait` could not wait for the next answer. `{ kind: "text", contains: "Answer", count: 2 }` passes when exactly two elements' own text contains "Answer". As on `net` and `signal`, the check keeps watching briefly after it first holds, so a copy that lands a moment later still counts. Unlike those, a wrong number of copies is not final, because a re-render can add or remove one: a reading taken mid-render sends the wait back to polling instead of ending it. A phrase split across child elements cannot be counted, so the check answers unknown and says so; the page now marks that match with `splitOwner`. A page whose SDK is older than 3.10.12 cannot mark it, so a count of one or more answers unknown there. Saving a flow keeps a counted text exact, where a text with a number is otherwise made word-level. Hidden copies count unless `visible: true` is set. `count: 0` means none, the same as `absent: true`, and `count` cannot be combined with `absent` or `satisfies`. A saved flow that uses it needs a platform on this core or newer, whose schema knows the field. Closes [#2291](https://github.com/reticlehq/reticle/issues/2291).
