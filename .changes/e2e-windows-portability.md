### Fixed

- **Four battery specs assumed POSIX and could not run on Windows — one of them passed while doing nothing.** The web battery runs on `ubuntu-latest` only, so nothing had ever exercised these there. `atlas-hard-fixture` died on `spawn pnpm ENOENT` (it is `pnpm.cmd` on Windows) and then on `process.kill(-pid)`, a process GROUP that Windows does not have; it now spawns through a shell there and stops the vite tree with `killTree`, whose `taskkill /T` is the same guarantee. `bridge-stress` asked for `shell: '/bin/sh'` (`spawnSync /bin/sh ENOENT`) for syntax node gives directly — `|| true` is a try/catch and `& echo started` is a detached spawn — so it no longer uses a shell at all. `daemon-heartbeat` looked up its listener with `sh -c lsof` and killed it with `kill -9`, neither of which exists on Windows; it now uses the netstat-backed `pidOnPort` and `killTree`. **`mcp-stress` was the dangerous one**: its `daemonPid` returned `null` whenever `lsof` threw — the same value it uses for "nothing is listening" — so `killDaemon` killed nothing ten times out of ten, the daemon went on holding the port and failed the squatter with `EADDRINUSE`, and the headline check reported **PASS at "killed 0/10"**. Surviving a kill is only evidence if a kill happened, so that check now requires one. Verified on Windows 11: atlas 8/8, bridge-stress 13/13, mcp-stress 18/18 (now killing 5/10 for real), daemon-heartbeat 7/9 — its last two are a separate, product-level gap in graceful shutdown on Windows, not a portability one.
