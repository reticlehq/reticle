### Fixed

- **`@reticlehq/engine`, `@reticlehq/browser` — error text written into an existing alert region acknowledges the failure, so the verdict is no longer `no` (`ui-advanced-request-failed`) or `unknown`.** A correct sign-in form got `no` when its login POST answered 401 and it wrote "Wrong email or password" into a `<div role="alert">` that was already on the page. Only a mounted alert counted. `dom.text` now carries `live` (`assertive` or `polite`) when the text changed inside a live region. Text in an assertive region (`role="alert"` or `aria-live="assertive"`), written after the failed call was sent, acknowledges the failure. Text in a polite region (`role="status"`), such as "Saved", does not. A plain element that says "Welcome back" over a failed sign-in is still `no`. Part of [#2173](https://github.com/reticlehq/reticle/issues/2173).
