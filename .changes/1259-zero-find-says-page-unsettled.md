### Fixed

- **`@reticlehq/server`: a `find` that ran before the page finished rendering answered 0 with nothing to say it was early.** Click a control that opens a modal after a fetch, then at once run `reticle_look { action: "find" }` for the modal's combobox: it answers 0 matches. `reticle_act` returns before an async render, and a find reads the page at one moment, so an agent read the 0 as "not there". A zero-match `find` (or `reticle_query`) that runs while the last act is still landing now carries `unsettled`. That is the case when a request the act started has not come back, or the DOM changed less than 500 ms ago. The field gives the reason and points at `reticle_assert { action: "wait" }` or `reticle_act_and_wait`. The read itself still does not wait. Part of [#1259](https://github.com/reticlehq/reticle/issues/1259).
