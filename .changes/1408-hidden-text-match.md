### Fixed

- **`@reticlehq/engine`, `@reticlehq/server`, `@reticlehq/core`: a `text` check passed as `verified: "yes"` when the only matching node was hidden.** A success template still hidden in the DOM satisfied `{ kind: "text", contains: "Thank you" }`, so "the request succeeded and the UI says so" read green when nothing was on screen. The hidden-match caveat only ran when the consequence was already true before the action. Now, when every element a `text` clause (or an `element` clause with no `state`) matched is hidden, `act_and_wait` and `assert` answer `unknown` with the new reason `hidden_match`, and the reason names `visible: true`. A visible match, or one visible among several hidden, is unaffected. Closes [#1408](https://github.com/reticlehq/reticle/issues/1408).
