### Fixed

- **`@reticlehq/server` — a lease on a deployed page with no SDK ended `sdk_never_dialled`.** The zero-install reader could not connect from a page that is not on loopback, so a lease on a deployed build or a production preview could not drive or read the page. Two things stopped it. The page's Content-Security-Policy blocked the dial to the daemon, and the daemon refused the page's origin. The lease now keeps the page's own CSP and adds only the daemon's WebSocket origin to its `connect-src`, in the CSP header and in a CSP `<meta>` tag. Every other part of the policy applies as the server sent it, so a CSP block that a real user sees still shows. The lease result says `cspWidenedFor` with that origin when it changed the page's policy. The reader also turns on zod's `jitless` setting in the page, so it never needs `unsafe-eval`: on a page whose CSP forbids eval (nextjs.org), the session stopped answering. It also gives the reader a single-use nonce for the page's origin in place of the machine's pairing token, so the pairing token no longer goes into a page that somebody else serves. Closes [#2016](https://github.com/reticlehq/reticle/issues/2016).
