### Fixed

- **`@reticlehq/browser`: a JSON request body sent as bytes, and a FormData upload, now carry a write identity.** A client that encodes JSON before sending it (Flutter web's HTTP client, gRPC-web) posts a `Uint8Array` or `ArrayBuffer`. That body got no shape fingerprint and no captured text, so every POST to its endpoint pooled into one unknown identity, and a correct fan-out graded `unknown / duplicate-request`. Bytes that decode as strict UTF-8 text are now treated exactly like a string body: the same fingerprint, plus the same redaction and cap under capture. Random binary keeps only `requestBodyType`. A FormData body is fingerprinted from its field names and kinds (a file's type and size), with text values counted only in a total length. It is still never captured. Closes [#1347](https://github.com/reticlehq/reticle/issues/1347).
