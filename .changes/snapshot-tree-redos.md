### Fixed

- **Reading a page snapshot no longer slows down on a line full of spaces.** The parser that turns the browser's snapshot tree into actionable elements used a second pattern to cut the `(ref=…)` token back out of each line, and that pattern began with an unbounded run of whitespace. Matching it against a line that ends up not carrying a ref makes the engine retry that run from every position, so the work grows with the square of the line's length rather than with the line. The tree describes a real page, so the long run is whatever the app puts on screen — a flagged polynomial ReDoS, on the path the harness uses to decide what to drive next.

  The token had already been located by the first pattern, so the second one was doing work that an index and two slices do without backtracking. It was not simply redundant: it also closed the gap left behind when a ref sits mid-line, and dropping it outright changed the description string — which crawl uses as an identity, so the dedupe would have quietly shifted. Trimming the prefix gives the identical string with no pattern to backtrack. The function had no tests at all; it has six now, written before the change so the equivalence is pinned rather than asserted.
