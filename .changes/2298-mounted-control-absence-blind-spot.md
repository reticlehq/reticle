### Fixed

- **`@reticlehq/core`, `@reticlehq/browser`, `@reticlehq/engine`, `@reticlehq/server`: A state check on one mounted control gave `unknown` beside a virtual list.** A check that a "Notify me" checkbox in a settings panel was not `checked` returned `verified: "unknown"` (`absence_blind_spot`) when the page also had a virtual list with unmounted rows. `reticle_assert` and `reticle_act_and_wait` now return `yes` for that check when the query has a ref `scope` (for example `scope: "e2"`) and the page proves that the scope is clear of every virtualized list. The scope must be a live element that is not inside a virtualized list and does not contain one, and the one mounted match must not be inside one. This applies to `not(element)` and to `absent: true`. All other queries stay `unknown`: a query with no `scope`, a CSS selector `scope`, a scope that is in a virtualized list or contains one, a bare role, multiple mounted matches, and a control that is not mounted. A virtual list repeats the same control in each row, so one mounted match does not prove that no unmounted row holds a match. The proof comes from the page: the `match` command has a new `outsideVirtualized` argument and answer. A page with an older `@reticlehq/browser` does not answer it, so the verdict there stays `unknown` until you update the page's `@reticlehq` packages. Closes [#2298](https://github.com/reticlehq/reticle/issues/2298).
