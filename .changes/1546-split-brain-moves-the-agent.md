### Fixed

- **`@reticlehq/server`: the `daemon_split` advice moves the agent instead of stopping the app's daemon.** When the app was connected to one daemon and the agent's MCP to another, the advice led with `reticle stop --port <the app's daemon>` and a dev server restart. That broke a working session the agent had not started, which may belong to a person, another agent or another project. The advice now says to set `RETICLE_PORT=<that port>` in this MCP server's config, or to launch the agent from the dev server's project directory, then restart the agent session and leave that daemon running. Stopping it comes last, only if nothing else uses it, with the warning that it disconnects every tab and agent on it. Closes [#1546](https://github.com/reticlehq/reticle/issues/1546).
