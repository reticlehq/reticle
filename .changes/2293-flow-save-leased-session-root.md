### Fixed

- **`@reticlehq/server` — `reticle_flow_save` wrote flows outside the project that a leased session tested.** When the daemon ran in another directory, a recording from a leased tab with a claimed `root` (or a different `projectId`) saved its flow under the daemon root whenever `reticle_flow_save` omitted `sessionId`. `reticle gate` and `reticle_verify { action: "flows" }` then could not find the flow. `reticle_flow_save` now uses the session that recorded the program, and `reticle_flow_save_recorded` honors the lease's claimed root. Closes [#2293](https://github.com/reticlehq/reticle/issues/2293).
