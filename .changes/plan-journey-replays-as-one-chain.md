### Fixed

- **`@reticlehq/server` — a plan rerun of a journey the Harness saved failed on an unchanged app.** The Harness saves a journey as a sign-in flow and a mid-session flow. On Run plan the second flow reloaded its start page before step 1, the in-memory sign-in was gone, its first element was not found, and the plan read "Failed" with "the flow needs re-anchoring, not the app fixing" under it. A journey's flows now replay as one chain: each flow after the first continues the page the one before it left (`reticle_flow_replay { at: 0 }`, newly accepted). A replay that could not anchor or run decides nothing about the app: the journey hands its goal to the model as its fallback, and with no fallback it reads undecided, never failed. A replay that ran and did not hold is still a regression and is never re-driven.
