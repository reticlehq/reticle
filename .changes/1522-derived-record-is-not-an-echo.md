### Fixed

- **`@reticlehq/engine`: an endpoint that returns a new record of the same type was graded `write-field-ignored`.** A transform such as "summarize this artifact" takes an artifact descriptor and returns a new artifact with its own hash, producer and kind. The field names matched the request, so every shared value was compared. Every one differed, and the verdict was `no` on a call whose declared `net` predicates all passed. Two changes stop this. A content-derived key (a hash, `sha*`, `md5`, a checksum or a digest) is now exempt like an identity key. When two or more compared keys all differ and the response names a different id or content hash, the response is read as a new record and the rule says nothing. That never applies to a PUT, a PATCH or an addressed write, so a server that ignores a whole update is still reported. A partial echo, where one key comes back as sent and another does not, is still reported. Closes [#1522](https://github.com/reticlehq/reticle/issues/1522).
