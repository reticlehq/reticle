### Added

- **`@reticlehq/browser/activate` — a loader that lets the Reticle dashboard connect to your staging and production deployments.** Production mode needed a site that redeemed the activation ticket on its own server, so only the Reticle dashboard could use it. Now a site calls `activate({ publicKey })` at startup. Without a `reticle_activate` parameter in the URL, it reads that one parameter and does nothing else: no SDK download, no socket, no storage and no DOM writes. With one, it checks the ticket's Ed25519 signature, expiry, origin and bridge in the page, removes the parameter from the address bar, and connects in production mode with the ticket's single-use nonce. A refused ticket loads nothing. `@reticlehq/core` adds `signActivationTicket` and `verifyActivationTicket` for the service that mints the tickets. See `docs/production-mode.md`.
