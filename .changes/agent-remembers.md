### Added

- **`@reticlehq/server`, `@reticlehq/init` — Reticle holds the memory, so a compacted agent does not lose it.** `reticle_context { compact: true }` and the new `reticle context --compact` CLI (no daemon needed) return one bounded resume block folded from the daemon's own records: the tab and route, the declared request, every claim that FAILED or is NOT PROVED by its latest verdict, what held, intents still owed, this app's notes, and the rules. `reticle init` installs a Claude Code `SessionStart` hook (matcher `compact`) that prints it straight back after a compaction; it is listed in init's plan and is removable like any hook.
- **The rules live where a compaction cannot reach them.** The Reticle section `init` writes into `CLAUDE.md` / `AGENTS.md` / the Cursor rule now opens with the eleven rules an agent needs on every call (only `yes` passes, declare `until` first, a journey is one `reticle_act { steps }`, exact-case text, how to target, read the failure before retrying, the predicate kinds, and run `context --compact` after a compaction). SKILL.md carries the same list. A tool result carries only a one-line pointer, once per session.
- **App notes.** A failed check whose diagnosis named the fix (the text is there in another case, the name is on a control with another role) becomes a note in `.reticle/app-notes.json` once a later passing check in the same session used that fix. Notes are surfaced in the first notices of a session and in the resume block, labelled as targeting hints; nothing that decides a verdict reads them.
- **Re-teach on a mistake.** When a call breaks a rule the primer covers (acting without `until`, an aliased predicate, a case-only miss, listing sessions a third time), its answer carries that one rule, once per session.
