### Added

- **`@reticlehq/server` — `reticle_crawl { exhaustive: true }` now drives edge cases and reports what they break.** Before, the exhaustive crawl typed one ordinary value into each field and pressed each control once, so a double submit, a value a reload loses, or a server error on an empty field was never tried. After it explores, the crawl now presses each control that sends a write twice (with and without a wait between the presses), reloads after the write, and types edge-case values into each field: empty, only spaces, over `maxlength`, a number below `min`, emoji and right-to-left text, and more. It also presses controls back to back, out of order and before the form is filled, and checks that a Cancel puts the page back. Controls that send a write go first. Edge cases get their own share of the action budget, so they never take actions from exploration. Each finding (`repeat-changed-state`, `lost-after-reload`, `undo-not-restored`, `shown-differs-from-sent`, `intermittent-result`, or the server error or page error an edge value caused) comes with the steps that show it and the element's `file:line`. The findings are in the crawl's `anomalies` and in `reticle_coverage { scope: "app" }`, and a control whose edge cases were driven is no longer an edge hole. Closes [#2201](https://github.com/reticlehq/reticle/issues/2201).
- **`@reticlehq/server` — the exhaustive crawl now breaks requests in the page that `reticle mcp --headless` drives.** Its failure paths asked only a browser started with `reticle drive` or `RETICLE_CDP_URL`, so on a leased page every failure path said "skipped". A write that already failed while the crawl explored (an API that is down) is now reported in `notSucceeded` and is not judged, because there is no success to compare its failure with.
