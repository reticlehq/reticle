### Fixed

- **`@reticlehq/server`: a session's counts no longer add up to more than happened.** The final `daemon_stopped` summary carried lifetime totals while every `session_progress` carried its own window, so summing a session's events counted each flushed window twice; the MCP proxy's flush did the same. Every count is now windowed on every event, the final one included, and the final event carries the session totals separately as `lifetimeToolCalls`, `lifetimeVerifications` and `lifetimeBugsFound`. The error-class, recovery, repeated-error, feedback-prompt and guessed-tool counts were never reset between windows at all; they are now. `docs/telemetry-contract.md` states the summing rule.
- **`@reticlehq/server`: error messages in telemetry are allow-listed.** A hostname, a Windows home directory with a space in it, a `~` path or a name in free text could reach the wire inside an error skeleton. Only a sentence Reticle itself writes, or a bare error code such as `ENOENT` or `TypeError`, is sent now; anything else is replaced by its fingerprint.
- **`@reticlehq/server`: feedback is redacted more thoroughly.** Home paths are redacted through spaces, Windows paths in every spelling, other absolute paths, `~` paths, hostnames and non-local IPs are removed, URLs lose their query and fragment and keep their host only when it is this machine, and a `trace` is reduced to tool names and verdict words. Reports left in the outbox by a failed send are now retried, re-redacted, when the daemon starts.
- **`@reticlehq/server`: telemetry events are validated before they are sent.** An event that fails the wire schema is dropped instead of sent, and an MCP client's name is capped to fit. The detached sender no longer puts the event body on its command line, where `ps` could read it.
- **`@reticlehq/server`: "first" onboarding steps fire once per machine and project.** They fired again on every daemon start, and `verdict_produced` on every verdict. They are now remembered under `~/.reticle/firsts/` and carry `firstEver: true`; `app_instrumented` still fires once per run and marks only the true first. `bug_found` rows carry an `occurrence` index, so two hits of one defect are no longer identical rows.
- **`@reticlehq/server`: telemetry says less that is not true.** A daemon or MCP server is no longer tagged `no_tty`, a crash is no longer attributed to the agent, an id that could not be saved is marked `idEphemeral`, unknown CLI flags and anything after `--` are reported as `other` or not at all, grouped tools' actions (`reticle_look { action: "find" }`) are reported by name instead of `other`, a Reticle source checkout no longer spends the machine's first-run when sending feedback, and `init_completed` is reported when setup stops early, throws or is interrupted. `RETICLE_INTERNAL=1` (or `~/.reticle/telemetry-internal`) marks every event `internal: true`, and `break/` runs with telemetry off.
