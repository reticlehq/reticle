### Fixed

- **`@reticlehq/core`, `@reticlehq/engine`, `@reticlehq/server` — the `no-store-registered` gap no longer tells an app with a bare-getter store that no store is registered.** `registerStore('app', () => state)` registers a readable store with no `subscribe`, so a `state` assertion passed off it while the same response said "no store is registered" and told the reader to call `registerStore(name, getState)`, the call they had already made. The gap now says no _subscribable_ store is registered, which is also true when nothing is registered or when the only store is the React adapter's own render meter, and the remedy asks for `registerStore(name, store)` or `registerStore(name, getState, subscribe)`. Closes [#1146](https://github.com/reticlehq/reticle/issues/1146).
