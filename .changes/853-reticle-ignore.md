### Added

- **`@reticlehq/core` + `@reticlehq/babel-plugin` + `@reticlehq/vite-plugin`: a file can opt out of source stamping with `// @reticle-ignore` on its first non-empty line.** The only lever before this was the plugin's `include`/`exclude` globs, which live in the bundler config, far from the file, and are the wrong shape when the reason to skip is local: a generated component, a snapshot test the stamp would break. A comment sits with the code and survives the refactor that moves the file. Whole file, first line, on purpose: the reasons are file-shaped, and a marker that worked from line 40 would be a marker nobody can find. `/* @reticle-ignore */` works the same way, and a `.svelte` component uses `<!-- @reticle-ignore -->` because it has no line for a `//` before its markup. The marker is a core constant so the two plugins and the docs cannot drift on it; the Babel plugin reads it once per file — so Vite, `@reticlehq/next` and direct Babel users all honour it — and the Vite plugin reads it ahead of both stampers so the Svelte path does too. It is not silent: the Vite plugin reports each opted-out file once, by name, in the dev-server output, so an opt-out is something a reader sees rather than something they discover months later from a `file:line` that never resolves. The stamping helpers moved to their own module when `index.ts` crossed the line cap. Part of [#853](https://github.com/reticlehq/reticle/issues/853). Contributed by @Chirag6722 in #946.
