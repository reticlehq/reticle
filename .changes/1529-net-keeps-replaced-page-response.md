### Fixed

- **`@reticlehq/engine`: a write that made the app navigate could not be proven with a `net` predicate.** A Delete button sends `DELETE /api/items/1` and, on 204, goes to `/`. Reticle drops evidence from a page that has been replaced. When the new page then made a request of its own, `net { method: "DELETE", status: 204 }` answered `no`, a failed mutation, although the server had answered 204. A server's response is a fact about the server, not about the page. So a `net` predicate now counts an answered request from the page that was just replaced when the request falls inside the `since` window, the cursor from before the action. `reticle_act_and_wait` always passes that cursor. Without a `since` floor the request could come from any earlier page, so it is not counted, but the answer is now `unknown` with the reason, not `no`. Closes [#1529](https://github.com/reticlehq/reticle/issues/1529).
