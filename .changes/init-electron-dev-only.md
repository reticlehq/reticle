### Fixed

- **`@reticlehq/init` — a packaged electron-vite app shipped Reticle's IPC shim and screenshot handler.** `init` wrote the preload shim (which patches `ipcRenderer.invoke` and exposes `__reticleIpc`) and `installReticleCapture` in main with no dev guard, although `@reticlehq/electron` says both must be dev-only. Both now sit behind a guard the bundler replaces at build time — `import.meta.env.MODE` in electron-vite, Forge's own `<NAME>_VITE_DEV_SERVER_URL` in a Forge main — so a production build carries neither, while `electron-vite dev` and a `--mode development` build keep IPC observation and screenshots. An unbundled CommonJS main is guarded on `app.isPackaged`. The preload shim now loads through a dynamic import, so it installs just after the preload body runs: an API exposed as `invoke: ipcRenderer.invoke` (the function itself, not a call through it) is no longer observed. Re-running `init` rewrites the unguarded lines an older version wrote. Electron Forge's preload gets the same guarded import: Forge bundles its preload into one file, so the shim is inlined under `electron-forge start` and absent from `electron-forge package`, and `init` adds the `vite/client` types reference Forge's tsconfig lacks.
