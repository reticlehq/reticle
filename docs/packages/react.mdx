`@reticlehq/react` is the Reticle kit for React apps, and usually the only SDK package a React user needs: it re-exports the whole browser SDK and adds fiber-tree work that maps a DOM node to its component stack, its hook state, and its source file. If your app is React, install this one and not `@reticlehq/browser`.

**Apache 2.0. Depends on `@reticlehq/browser` and `@reticlehq/core`. Peer dependency: `react >= 18`.**

## Why it exists

This is the package that turns "the button is broken" into `src/components/Login.tsx:81`. Finding a bug is half the job; Reticle's answer to the other half lives here.

```bash
npm i -D @reticlehq/react
```

## It re-exports the browser SDK

`export * from '@reticlehq/browser'` is in the barrel, so one install gives you `reticle`, `registerCapabilities`, every store adapter, and everything else on the [browser page](/packages/browser). You do not add `@reticlehq/browser` separately.

```ts
import { reticle, install } from '@reticlehq/react';

install();
// reticle.local.js holds this machine's pairing token. Do not commit it.
import('./reticle.local.js')
  .catch(() => ({}))
  .then((local) => reticle.connect({ token: local.token }));
```

The bridge refuses a connect without the pairing token, also on localhost. `reticle init` writes `reticle.local.js` and adds it to `.gitignore`. Without init, make it from `~/.reticle/pairing-token` as the [browser page](/packages/browser) shows.

## Exports

### Setup

| Export | Signature | What it does |
| --- | --- | --- |
| `install` | `(options?: InstallOptions): void` | Idempotent. Registers the `react` adapter and installs the render meter. Call it once, before `connect()` |

#### `InstallOptions`

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `discoverStores` | `boolean` | `true` | When `true`, `install` walks the React fiber tree after each of the first ten commits and registers stores it finds in Redux `Provider`, TanStack `QueryClientProvider`, and similar context providers. Set to `false` to skip auto-discovery. Use this when your app has more than one context provider and you want only the stores you name with `registerStore` to appear in `reticle_look`. The render meter still runs. |

```ts
// Only expose the store you control:
install({ discoverStores: false });
registerStore('safe', safeStore);
```

The [Vite plugin](/packages/vite-plugin) injects `install()` and `reticle.connect()` for you. In Vite, pass `discoverStores: false` to the plugin (`reticle({ discoverStores: false })`) to disable auto-discovery. With manual setup, pass `{ discoverStores: false }` to `install()` before calling `reticle.connect()`.

### Mapping a node to its component

| Export             | Signature                                |
| ------------------ | ---------------------------------------- |
| `identify`         | `(el: Element) => ComponentInfo \| null` |
| `readState`        | `(el: Element) => ComponentStateResult`  |
| `hasHoverHandlers` | `(el: Element) => boolean`               |
| `relativeToRoot`   | `(file: string) => string`               |

`identify` walks the fiber tree to build the component stack and source location. `readState` reads hook state, bounded. `relativeToRoot` turns an absolute source path into a repository-relative one using the root the plugin stamped.

### Render measurement

`installRenderMeter`, `resetRenderMeter`, `getRenderStats`, and the `RenderStats` type. This is what makes a render loop visible as a number rather than a hunch.

`RenderStats` has two fields, and the `__reticle_renders` store reports both:

| Field | Type | What it says |
| --- | --- | --- |
| `commits` | `number` | React commits since `install()`. |
| `hydration` | `HydrationState` | `none`: no React root on the page. `pending`: a root, or a Suspense or Activity boundary in it, is still dehydrated, so its server-rendered controls have no handlers. `done`: nothing waits for hydration. `unknown`: the adapter could not read the tree to the end. `done` stays once reached; before that, each read looks at the page again. |

Flow replay reads `hydration` on each page that loads (the start page and each `navigate` step). It waits only while the value is `pending`. `HydrationState` comes from `@reticlehq/core`.

### Hydration

`HYDRATION_COMPLETE_SIGNAL`, `createHydrationTracker`, types `HydrationTracker` and `HydrationRead`.

`install()` fires `reticle:hydration-complete` once, when the page reads `done`. That is at the first React commit after which no part is dehydrated, or at `install()` when React hydrated the page before it. A commit that leaves a Suspense boundary dehydrated does not fire it. A page with no React tree never fires it.

| Export | Signature |
| --- | --- |
| `createHydrationTracker` | `(onHydrated: () => void, read?: HydrationRead) => HydrationTracker` |
| `HydrationRead` | `(roots: readonly unknown[]) => HydrationState` |
| `HydrationTracker` | `{ onCommit(root?: unknown): void; onInstall(): void; isHydrated(): boolean; state(): HydrationState }` |

Without `read`, a tracker fires on the first commit, as before, and `onInstall` does nothing. With `read`, it fires on the first `onCommit` or `onInstall` that reads `done`. `onCommit` keeps each FiberRoot it gets, and gives them all to `read`.

### Error boundaries

`buildErrorBoundaryData`, `reticleOnCaughtError`, type `ErrorBoundaryData`. Wire `reticleOnCaughtError` into React's `onCaughtError` and a boundary that swallows an error stops being invisible.

### Hydration mismatches

`buildHydrationErrorData`, `isHydrationMismatch`, `reticleOnRecoverableError`, type `HydrationErrorData`.

### Commits and CDP

`createCommitAggregator`, type `CommitAggregator`. `readComponentAt`, `buildReaderExpression`, `parseComponentRead`, type `CdpComponentRead`.

## The `./store` subpath

One export, and the only module in the package that imports React:

```ts
import { useState } from 'react';
import { useReticleStore } from '@reticlehq/react/store';

function Cart() {
  const [items, setItems] = useState([]);
  useReticleStore('cart', items); // now readable via reticle_look { action: "state" }
}
```

`useReticleStore(name: string, value: unknown): void`.

## Source mapping needs a build step

React 19 dropped `_debugSource`, so `identify` can name the component but not the file unless something stamps the source at build time. That is [`@reticlehq/babel-plugin`](/packages/babel-plugin), pulled in for you by [`@reticlehq/vite-plugin`](/packages/vite-plugin) or [`@reticlehq/next`](/packages/next).
