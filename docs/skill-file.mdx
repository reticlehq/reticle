`SKILL.md` is one short document written for a coding agent. Paste its URL into the agent and say "read this and set up Reticle":

```
https://raw.githubusercontent.com/reticlehq/reticle/main/SKILL.md
```

The URL always returns the current version. The same file ships inside the package, so an agent with no network can read it from disk:

```
node_modules/@reticlehq/server/SKILL.md
node_modules/@reticlehq/server/docs/
```

The `docs/` folder beside it is a copy of this site.

## What it tells the agent

It is the critical path and nothing else. Read [SKILL.md](https://github.com/reticlehq/reticle/blob/main/SKILL.md) itself to get the rules exactly right; in short:

- **First move:** if the `reticle_*` tools are visible, call `reticle_session { action: "list" }`. If they are not, hand the user the installer line and stop.
- **Setup is `init`, then the first run.** `init` wires the app and waits for a session. It never drives. A dev server that was already running must be restarted once.
- **Done means a verdict.** A session listed means the SDK reached the page. Setup is finished when the first run returns a verdict.
- **Only `verified: "yes"` is a pass.** `unknown` means Reticle could not tell. Never weaken a check to make it pass.
- **Replay before you drive.** `reticle_verify { action: "change" }` or `{ action: "flows" }` re-verifies saved journeys in one call.
- **Report problems with Reticle** through `reticle_session { action: "feedback" }`, or `reticle feedback --agent` from the shell.

## Do you need it?

Often not. The installer registers the MCP server with your agents, and `reticle init` writes agent rule files and a `/reticle` command for Claude Code. The SKILL file is for agents `init` cannot configure, for a from-scratch install, or for an agent you want to hold the rules in context.
